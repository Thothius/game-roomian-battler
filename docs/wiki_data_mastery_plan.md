## The Plan — 5 Phases

### Phase 1: Wiki API Full Entity Crawl (4-6 hours)

**Goal:** Download and cache every wiki page for every entity category, not just guns/items.

**Approach:** Use the MediaWiki API at `enterthegungeon.wiki.gg/api.php` to enumerate category members, then fetch each page's raw wikitext (cleaner than HTML scraping).

```
API endpoint: https://enterthegungeon.wiki.gg/api.php
  ?action=query&list=categorymembers&cmtitle=Category:Bosses&cmlimit=500&format=json
  ?action=parse&page=Bullet_King&prop=wikitext&format=json
```

**New script:** `scripts/crawl_all_wiki.py`
- Enumerate all categories via `list=allcategories`
- For each target category (Bosses, Enemies, NPCs, Pickups, Objects, Chests, Status Effects, Achievements, Chambers), fetch all member pages
- Cache raw wikitext to `cache_wikigg/categories/`
- Throttle: 0.5s between requests, 2 concurrent workers max
- Resume support via progress JSON

**New data files:**
| File | Source Category | Fields to Extract |
|------|----------------|-------------------|
| `assets/data/bosses.json` | Category:Bosses (43 pages) | name, floor, hp, dps_cap, drops, master_round, behavior_summary, wiki_url, image |
| `assets/data/enemies.json` | Category:Enemies (212 pages) | name, base_hp, damage, behavior, floor_range, jammed_hp, wiki_url, image |
| `assets/data/npcs.json` | NPCs page + links | name, location, service, description, unlock_condition, wiki_url, image |
| `assets/data/pickups.json` | Pickups page | name, type, drop_source, mechanics, wiki_url |
| `assets/data/objects.json` | Objects page | name, behavior, interaction, wiki_url |
| `assets/data/chests.json` | Chest page + links | name, quality_odds, mimic_chance, fuse_chance, wiki_url |
| `assets/data/status_effects.json` | Category:Status Effects | name, effect, duration, sources, wiki_url |
| `assets/data/chambers.json` | Chamber pages | name, floor_num, hp_multiplier, dps_cap, boss_pool, room_count, wiki_url |
| `assets/data/achievements.json` | Achievements page | name, condition, reward, wiki_url |

**Parser:** `scripts/parse_wiki_entities.py`
- Parse wikitext (not HTML) for each entity type
- Extract infobox fields using wikitext template parsing: `{{Infobox|hp=100|floor=1|...}}`
- Fallback to section-based extraction for pages without infoboxes
- Output structured JSON per entity type

### Phase 2: Synergy Validation & Effect Text Verification (2-3 hours)

**Goal:** Close the highest-risk data gaps.

**2A: Synergy Diff Script** — `scripts/validate_synergies.py`
- Run `parse_wiki_data.py::parse_synergies()` on the cached `Synergies.html` master table
- Diff each synergy's `items[]` and `any_of[]` against `synergies.json`
- Report: missing synergies, missing items in synergies, name mismatches
- `--repair` flag: auto-add missing items to synergies.json

**2B: Ammonomicon Entry Diff** — Add to `validate_db.py`
- Extract `druid-data-desc` (Ammonomicon Entry) from each cached wiki page
- Diff against `effect` field in items.json / `notes` field in guns.json
- Report mismatches — don't auto-repair (prose may be intentionally edited)

**2C: Fix 13 Missing Cache Pages**
- Fix `enrich_from_wikigg.py` slugify to handle apostrophes & parens
- Re-fetch the 13 holes (Old Knight's Helm, Oiled Cylinder, etc.)
- Re-run `parse_wiki_rich.py` to populate their `wiki` fields

### Phase 3: Structured Tag System Upgrade (3-4 hours)

**Goal:** Move from regex-heuristic tags to wiki-verified structured tags.

**3A: Gun Class → Element Mapping (Already Done)**
- Guns have `gunClass` field from wiki: FIRE/ICE/POISON/CHARM/EXPLOSIVE
- `ElementalTagger` already uses this reliably for guns — no change needed

**3B: Item Tag Enrichment from Wiki Sections**
- Parse the `Effects` section from each item's `wiki` field (already cached)
- Extract structured tags from known patterns:
  - "Grants X armor" → `armor` tag with value X
  - "Increases damage by X%" → `damage_up` tag with value X
  - "Chance to freeze" → `freeze` tag
- Create `scripts/extract_item_tags.py` that outputs a `tags` array on each item in items.json
- Tags include extracted numeric values where possible (e.g. `{"tag": "damage_up", "value": "+30%"}`)

**3C: New Tag Types**
Add tags we're currently missing:

| `charge` | "charged shot", "hold to charge" | Charge Cannon, BSG |
| `spread` | "spread of N bullets", "N projectiles" | Shotgun, Mailbox |
| `homing_bullets` | "homing" (already have) | — |
| `ricochet` | "ricochet", "bounce off walls" | already have `bouncing` |

## Technical Notes

### MediaWiki API Usage
```
# List all pages in a category
GET https://enterthegungeon.wiki.gg/api.php?action=query&format=json&list=categorymembers&cmtitle=Category:Bosses&cmlimit=500

# Get raw wikitext for a page
GET https://enterthegungeon.wiki.gg/api.php?action=parse&format=json&page=Bullet_King&prop=wikitext

# List all categories
GET https://enterthegungeon.wiki.gg/api.php?action=query&format=json&list=allcategories&acprop=size&aclimit=50
```

**Rate limiting:** 0.5s between requests, max 2 concurrent. The wiki.gg API returned 429 (Too Many Requests) during testing — must be respectful.

### Existing Infrastructure Reuse
- `enrich_from_wikigg.py` caching pattern → reuse for new entity types
- `parse_wiki_rich.py` token parser → reuse for entity page sections
- `validate_db.py` diff pattern → reuse for synergy validation
- `EffectTagger` pattern → extend with new tag types
- `RunProvider` special item tracking → extend with new tracked items
- `item_detail_screen.dart` tracking widgets → extract as reusable pattern

### Data Flow
```
Wiki API → cache_wikigg/ (HTML + wikitext)
                ↓
    parse_wiki_entities.py (new)
                ↓
    assets/data/{bosses,enemies,npcs,...}.json (new)
                ↓
    Flutter models (lib/models/) → RunProvider → UI screens
```

### Reference: dsegovia90/gungeon-api
A GitHub project that scrapes the Enter the Gungeon wiki and provides a REST API. Worth studying their parser approach, but our infrastructure is already more advanced for guns/items.
